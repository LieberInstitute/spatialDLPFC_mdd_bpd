# Targeted SuSiE colocalization execution plan

1. Audit the handoff against current official coloc, susieR, tensorQTL, and
   1000 Genomes documentation and the installed package source.
2. Verify approved GWAS paths and checksums, final target definitions, dense
   tensorQTL inputs, genotype/covariate samples, and candidate reference LD.
3. Implement a fresh, isolated MAPK3 pilot with explicit allele harmonization,
   exclusion logs, signed LD validation, and reproducibility metadata.
4. Run direct `susieR::susie_rss()` and `coloc::runsusie()` with identical
   effective inputs and settings, compare their underlying fits, and run
   `coloc.susie()` through both supported routes.
5. Record diagnostics, timings, memory, package/source provenance, checksums,
   and all exclusions without changing production outputs or running ABF.
6. Build and review the remaining-target manifest and resource estimate from
   the final `coloc_pass` table, collapsing overlapping windows only for input,
   LD, and fit reuse while retaining every comparison row.
7. User authorization received 2026-08-19: if the MAPK3 checks converge, run
   the validated `runsusie()` path for all remaining approved target regions.
   Use checkpointed, resource-capped parallel workers after profiling actual
   CPU, memory, storage, and thread use. Aggregate and audit all 100 targets.
8. Build the reference subset freshly from the University of Washington
   SeqArray conversion of the exact official 2022 1000 Genomes 30x phased
   panel, then record its immutable URL, checksum, variant/sample counts, and
   every allele-specific exclusion.
9. After aggregation, compare SuSiE read-only with the existing final ABF
   results. Emphasize DEG genes and high-H3 ABF cases, and distinguish signal
   resolution from independent validation. Do not rerun `coloc.abf()`.

The full-23andMe inputs, old coloc caches, production outputs, and non-target
regions are out of scope.
