# pySCENIC environment bundle

This bundle recreates the Linux x86_64 `pyscenic_bioconda` environment from the confirmed `pyscenic_JT.yml` export. The names differed in the exports; the dependency lists matched. Python is pinned to 3.10.14.

## Recreate the environment

Run these commands from the repository root on Linux x86_64:

```bash
module load python
module load conda
conda create --name pyscenic_bioconda --file reproducibility_inputs/conda-linux-64.lock
conda activate pyscenic_bioconda
cd reproducibility_inputs
python -m pip install --no-deps --require-hashes -r requirements-pip.lock
```

The Conda explicit lock pins package URLs and builds. The pip lock lists every exact pip package version from the export with SHA-256 hashes. It uses `--no-deps` because the export already records the complete pip package set, and all package dependencies are pinned there or in the Conda lock.

## Files

- `pyscenic_JT.yml`: untouched JHPCE environment export used as the reference.
- `environment-conda.yml`: canonical-name Conda-only source spec, with the machine-specific `prefix` removed.
- `conda-lock-conda.yml`: unified Linux Conda resolution generated by conda-lock 4.0.4.
- `conda-linux-64.lock`: explicit Linux x86_64 lock containing the 148 exact Conda artifacts listed in `environment-conda.yml`.
- `generate_conda_explicit.py`: selects those exact artifact URLs and checksums from the conda-lock resolution.
- `pyscenic_bioconda-after-conda-lock-install.yml` and `conda-linux-64-after-conda-lock-install.lock`: read-only diagnostics of the active JHPCE environment after conda-lock was installed into it.
- `requirements-pip.in` / `requirements-pip.lock`: exact pip pins and artifact hashes.
- `wheels/`: the patched pySCENIC wheel and the Arboreto 0.1.6 wheel installed after Conda setup.
- `pySCENIC-source/` and `pyscenic.patch`: source snapshot, base commit, and patch used to build the pySCENIC wheel.
- `arboreto-dist/`: original Arboreto wheel and source archive from JHPCE.
- `generate_pip_lock.py`: regenerates PyPI hashes from the exact pip pins and hashes the local wheels.
- `SHA256SUMS.txt`: checksums for the two wheel artifacts, the Arboreto source archive, and the pySCENIC patch.

## Regenerate lock artifacts

With conda-lock 4.0.4 available:

```bash
conda create --name mbv-lock-tools python=3.10 pip
conda activate mbv-lock-tools
python -m pip install conda-lock==4.0.4
conda-lock lock --file reproducibility_inputs/environment-conda.yml \
  --platform linux-64 \
  --lockfile reproducibility_inputs/conda-lock-conda.yml
python reproducibility_inputs/generate_conda_explicit.py
python reproducibility_inputs/generate_pip_lock.py
```

The full conda-lock resolution adds five transitive packages because the pip requirements are locked separately. The explicit installer file keeps only the exact Conda builds in the saved export; the pip lock then installs the exported pip versions, including versions that satisfy some overlapping dependencies.

The active JHPCE environment was used to install conda-lock itself before this work. Its later export includes conda-lock and 39 supporting pip packages, upgrades `filelock` from 3.15.4 to 3.32.7, and moves `cffi`, `python-fastjsonschema`, and `typing_extensions` from the Conda list to the pip list. That post-tool export is retained for comparison and is not the target environment. I used the saved pre-tool `pyscenic_JT.yml` as the pipeline baseline, as confirmed earlier. Install conda-lock in a separate tool environment in future.

This bundle has not yet been installed into a fresh Linux environment for comparison. It records the confirmed baseline package pins and checksummed artifacts, but that final reproduction check remains outstanding.
